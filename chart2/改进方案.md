## 案例 2: Zoomable Sunburst 改进方案

### 问题诊断 → 改进对照表

| # | 原问题 | 改进方案 | 涉及原理 | 实现状态 |
|---|---|---|---|---|
| 1 | 角度感知精度差，跨分支难比较精确数值 | 悬停 **Tooltip** 显示节点名称、层级路径、精确数值、占父级百分比、占总体百分比和子节点数 | 精确性补偿：用按需详情（Detail-on-Demand）弥补感知通道的精度不足 | ✅ 已实现 |

| 7 | 缺颜色图例，无法快速将颜色与分类名称对应 | 顶部水平 **颜色图例条**，钻取时动态更新为当前层级的子分类名称 | Gestalt 相似性：图例色块与弧段颜色建立跨区域关联 | ✅ 已实现 |

| 10 | 无一键重置功能 | 添加 **"回到根节点"按钮**，一键返回全局视图 | 交互效率：提供快捷重置路径 | ✅ 已实现 |

### 改进后的核心特性详解

#### 1. 色盲友好配色体系

**问题**：原始版本使用 `d3.interpolateRainbow`，该色板在色相环上均匀采样，但对色觉障碍用户（尤其是红绿色盲，影响约 8% 男性）极不友好——红-绿相邻色相几乎无法区分。

**改进**：
- 顶层使用 `d3.schemeTableau10`，这是 Maureen Stone 专门为 Tableau 设计的 10 色定性色板，经过 Protanopia、Deuteranopia 和 Tritanopia 三种色盲模拟测试
- 同分支子节点通过 CIE Lab 色彩空间的 L（亮度）通道递变：`c.l = Math.min(95, c.l + relativeDepth * 8)`
- Lab 色彩空间的 L 通道近似人眼的感知亮度，确保亮度差异与主观感受成正比（相比 RGB 直接调节更符合感知均匀性）

```javascript
// chart2.html 中的核心配色逻辑
const palette = d3.schemeTableau10; // 色盲友好色板

function colorOf(d) {
  const base = palette[colorIndex % palette.length];
  const c = d3.lab(base);
  c.l = Math.min(95, c.l + relativeDepth * 8); // Lab 亮度递变
  return c.formatHex();
}
```

#### 2. 钻取时的动态颜色重映射

**问题**：原始版本中颜色固定映射到顶层分类，钻入深层后，可见的弧段可能全部使用同一颜色（因为它们属于同一顶层分类），颜色完全失去区分力。

**改进**：每次钻取时，`colorOf()` 函数根据当前聚焦节点（`focusNode`）重新查找颜色索引。这使得 Tableau10 的 10 种颜色始终分配给当前可见的直接子项，确保每一层级都有良好的颜色区分。

```javascript
function colorOf(d) {
  let p = d;
  while (p.parent && p.parent !== focusNode) p = p.parent;
  // focusNode 的直接子项获得不同颜色
  const colorIndex = focusNode.children.indexOf(p);
  return palette[colorIndex % palette.length];
}
```

过渡动画中通过 `attrTween("fill", ...)` 实现颜色平滑插值，避免视觉跳跃：
```javascript
.attrTween("fill", function(d) {
  const oldColor = d3.color(this.getAttribute("fill"));
  const newColor = d3.color(colorOf(d));
  const interp = d3.interpolate(oldColor, newColor);
  return tt => interp(tt);
})
```

#### 3. 多通道数值编码

**问题**：Cleveland & McGill（1984）的实证研究将视觉编码的准确性排序为：位置 > 长度 > 角度 > 面积。Sunburst 主要依赖角度编码，其感知精度有限。

**改进**：采用多通道冗余编码策略，通过不同视觉通道传递同一组数值信息：

| 视觉通道 | 编码方式 | 精度 | 场景 |
|---|---|---|---|
| 角度（Angle） | 弧段角度大小 | 低精度，概览用 | 快速定位最大/最小分支 |
| 颜色亮度（Luminance） | 同色相内亮度递变 | 中精度，分组用 | 区分同族内的层级 |
| 文本标签（Text） | 弧上名称 + Tooltip 数值 | 高精度，按需获取 | 精确比较和详细分析 |
| 长度（Length） | 左侧表格中的条形图 | 高精度 | 直接比较子项大小 |
| 百分比数字（Number） | 中心环外的百分比标注 | 精确数值 | 快速读取占比 |

这种"低精度概览 + 高精度按需获取"的设计符合 Shneiderman 的信息可视化 mantra：**Overview first, zoom and filter, then details on demand**。

#### 4. 面包屑导航与中心信息卡

**问题**：钻取交互的核心风险是用户迷失在深层级中，忘记当前所处的层级位置和上下文。

**改进**：
- **面包屑路径**（`#breadcrumb`）：显示从根到当前节点的完整路径，每级可点击跳转。这满足了用户的 **方向感（Orientation）** 需求——在任何时刻都能回答"我在哪里"和"我怎么回去"。
- **中心信息卡**（`#center-info`）：在旭日图的中心圆内显示当前聚焦节点的名称、总值和占总体百分比。中心位置利用了视觉注意力的天然聚焦点（人眼倾向于首先注视图形的几何中心），确保用户第一时间获取上下文信息。

#### 5. 左侧文件管理器表格

**问题**：仅靠旭日图的弧段难以进行精确的数值比较，尤其是当子项数量较多时，弧段角度差异变得难以分辨。

**改进**：左侧表格以列表形式展示当前节点的所有子项，每行包含：
- **名称**（`row-name`）：对应弧段的分类名
- **占比条形图**（`bar-fill`）：用长度编码占比，颜色与旭日图弧段对应（Gestalt 相似性原则）
- **数值**（`row-value`）：精确数值
- **子项数**（`row-children`）：是否可继续钻取

点击表格中有子项的行可触发钻取，实现图表与表格的双向联动。这种"概览图 + 详情表"的组合布局（Cockburn et al., 2008 的 Focus+Context 范式）是信息可视化中常见且有效的设计模式。

#### 6. 百分比环形刻度条

**问题**：旭日图的角度编码精度有限，用户难以准确读出各子项的占比数值。

**改进**：在中心圆外圈（内径 130px，外径 148px）绘制一个小型环形图，每个弧段标注对应子项的百分比数值。弧段过窄（< 10°）时自动隐藏文字标签但保留色块。这提供了一个"轻量级饼图"作为辅助参考，使用户无需悬停 Tooltip 即可获取大致的数值信息。

### D3.js 实现要点

改进后的可视化使用纯 D3.js v7 实现，核心实现要点如下：

1. **层次布局**：`d3.hierarchy()` + `d3.partition()` 生成极坐标分区布局
2. **弧段生成器**：`d3.arc()` 带 padding 避免弧段完全贴合
3. **钻取动画**：`transition().duration(750)` + `tween("data", ...)` 插值实现平滑的缩放旋转动画
4. **颜色插值**：`d3.interpolate(oldColor, newColor)` 在 `attrTween` 中实现颜色平滑过渡
5. **百分比环**：独立的 `d3.arc()` 生成器 + `join(enter/update/exit)` 模式实现数据驱动的环形更新
6. **表格联动**：`d3.select("#table-body").selectAll().data().join()` 模式实现表格的动态更新
