# QuakeSpotter 0.2 — 世界地震可视化改进全记录

***

## 第 0 步：搭一个能独立跑的架子

### 改了什么？

原版是 ObservableHQ 上的一个笔记本——这玩意儿只能在 Observable 平台里面跑，没法下载下来直接用。我们用 **一个自包含的 HTML 文件** 完全复刻了它。

成果：一个双击就能打开的 HTML 文件

## 第 1 步：把地震点涂上不同颜色——原来都是一个红色

### 原来的问题

原版所有地震点**统一是红色的**。很多个点叠在一起，分不清哪个是大震哪个是小震。

环太平洋地震带密密麻麻一片红，根本看不出

### 改进思路

震级是一个连续的数字（2.1 级、3.7 级、5.2 级、7.8 级……），那我们就不应该用"一个桶装所有人"的颜色方案。应该让颜色也**连续变化**——小震是温和的颜色，大震是警示的颜色。

<br />

效果？

原来：2.0 级和 2.9 级看起来完全一样，不可区分

现在：相邻 0.1 级就有肉眼可辨的色差，地震带上的"热点"一眼可见

## 第 2 步：给地震点加深度信息——浅的鲜艳，深的褪色

### 原来的问题

地震不仅在平面位置上有区别，**深度**也是关键信息。比如日本附近有一群 10km 深的浅源地震（破坏力大）和一群 500km 深的深源地震（几乎无感）——原版里它们颜色一样，你根本分不出来。

### 改进思路

浅源地震 = "近在眼前" → 视觉上应该鲜明、扎眼\
深源地震 = "深埋地下" → 视觉上应该淡褪、不抢眼

这个直觉很自然

### 效果？

现在你一眼就能看出：那些特别鲜艳的点是浅源地震（可能破坏力大），那些灰扑扑的淡点是深源地震（对人类影响小）。数据多了一个维度。

## 第 3 步：给每个地震点画个边框——别让重叠的圆融成一团

### 原来的问题

在环太平洋地震带、日本附近，几十个地震点挤在一起，圆和圆之间没有边界，糊成一大坨，你根本不知道那里有几个地震。

### 改进思路

给每个圆画个细细的半透明描边——就像你在白纸上画的圆圈，有边界的圈即便叠在一起也能看出"这是两个圈"。

### 效果？

在密集区域（比如日本东北海域），你能清楚地看到"哦这里有 5 个小圆和一个大圆叠在一起"，而不是"这里有一团颜色"。

## 第 4 步：鼠标悬停弹出信息卡

### 原来的问题

鼠标在地球上晃来晃去，啥反应都没有。这个红点是什么地震？多大？什么时候发生的？完全不知道。

### 改进思路

鼠标在哪，就搜索离鼠标最近的那个地震点，弹出一个信息卡片。这个思路像地图 App 上"点击标记看详情"一样自然。

### 具体怎么改的？

用 `projection.invert()` 把鼠标的屏幕坐标反算成经纬度，然后用 `d3.geoDistance()` 计算鼠标位置和每个地震点的球面距离，找到最近的那个。距离小于 0.05 弧度（大约 3° 视角）就弹出 Tooltip。

### 效果？

鼠标悬停任一地震点 → 弹出：

- 📍 地点名称 + 震级徽章
- 🕐 发生时间
- 📏 震级 + 深度
- ⚠ 是否有海啸预警

## 第 5 步：顶部加统计栏——一眼看清全局

### 原来的问题

打开页面看到一堆点，但"今天/本周地震多不多？""最大的有多大？"——没有人告诉你。

### 改进思路

在地球上方加一行数据摘要，就像仪表盘上的指标卡。

### 具体怎么改的？

数据从 USGS 的 GeoJSON 返回后，立刻计算：

- 地震总数（`features.length`）
- 最大震级（`d3.max(mags)`）
- 平均震级（`d3.mean(mags)`）
- 最深震源（`d3.max(depths)`）

然后直接写到 DOM 里。

### 效果？

```
📊 地震总数 347    🔴 最大震级 6.8    📏 平均震级 3.2    ⬇ 最深震源 180 km
```

打开页面就能感知"本周地震活跃程度"。

## 第 6 步：点击聚焦——深入分析单个地震

### 原来的问题

你盯着一个大地震想看详细数据？对不起，原版不支持。

### 改进思路

点击一个地震点 → 地球自动转过去，把这个地震放到屏幕正中央，稍微放大，让周围的地震点淡出，然后在旁边弹出一个详细信息面板。这就像"聚焦模式"。

### 具体怎么改的？

1. **屏幕坐标缓存**：每帧绘制时，顺便把每个地震点的屏幕坐标存下来
2. **点击命中**：先用屏幕坐标快速检测（15px 半径），没命中的话再用球面距离高精度匹配
3. **旋转动画**：`targetRotX = -经度`，`targetRotY = -纬度`，用 ease-out cubic 缓动 1.2 秒平滑转过去
4. **缩放**：`targetScale = 1.3`，让你看得更清楚
5. **其他点弱化**：透明度降到 8%，几乎看不见，不干扰你
6. **脉冲光晕**：选中点周围 3 层周期性扩散的橙色圆环（相位各错开 0.33），像"呼吸"一样
7. **中心高亮**：白色小圆点在中心，强化视觉焦点
8. **详情面板**：右侧弹出，显示时间/震级/深度/经纬度/观测站距离/海啸预警/USGS 源链接

### 效果？

点击一个 M6.8 的大地震 → 地球平滑转过去，光晕脉冲，面板显示全部元数据，周围其他点全部淡出——沉浸式分析体验。

## 第 7 步：按住鼠标拖拽旋转地球——我想看哪儿就看哪儿

### 原来的问题

原版地球只能**按固定速度自动旋转**，你没法手动翻转到想看的地方。想看看日本地震带？等它自己转过来太麻烦

。

### 改进思路

鼠标按住拖拽 → 地球跟着手指转。这和 Google Earth 的交互一样——直觉告诉你就该这样。

### 效果

按住拖拽 → 自由旋转到地球上任意位置

快速甩一下松手 → 惯性滑行约 1.5 秒，像真实的地球仪

轻轻点一下（没拖动）→ 还是点击聚焦地震

完全不会误触——因为我们设了 1.5px 的抖动阈值，你手指微微抖一下不会被当成拖拽。

## 第 8 步：惯性滑行——松手后地球继续转一会儿

### 原来的问题

原版没有拖拽功能，更别说惯性了。但我们加上拖拽后，如果松手就立刻停住，会感觉很生硬。

### 改进思路

就像你用手转动一个真实的地球仪——用力甩一下，松手后它还会自己滑一段才停。这叫"惯性"。

### 效果？

快速拖拽松手 → 地球平滑滑行约 1.5 秒 → 自然过渡回自动旋转。手感"物理"。

## 第 9 步：缩放控制——远看全局近看细节

### 原来的问题

地球永远一个大小。不能放大看

加一组缩放按钮（+ / − / 重置），再加鼠标滚轮支持。像看地图一样，滚轮放大缩小是最自然的事。

### 具体怎么改的？

- 三个按钮：放大 (+0.15×/步) / 缩小 (−0.15×/步) / 重置 (1.0×)
- 鼠标滚轮：向上滚放大，向下滚缩小
- 范围：0.6× \~ 2.5×
- 倍率标签实时显示，带 `aria-live="polite"` 无障碍播报
- 按钮默认隐藏，鼠标悬停在地球上时平滑滑入

### 效果？

滚轮一滚 → 拉近看某个地震带的细节，再滚 → 拉远看全球分布。节奏完全在你自己手里。

# 第 10 步\*：修好"白屏"问题——告诉你数据加载到哪了

### 原来的问题

有一段时间用户反馈"什么都看不到"——打开就是白屏或者只有一个蓝色的球。排查下来，发现两个原因：

1. **用** **`file://`** **打开文件**：浏览器安全策略会阻止 `fetch()` 从 `unpkg.com` 和 `earthquake.usgs.gov` 加载数据。直接双击 HTML → 数据加载失败 → 什么也不显示。
2. **加载失败不报错**：原版的 `.catch()` 只写了一句 `console.error()`，普通用户根本看不到。

### 改进思路

1. 所有 fetch 失败时，往页面 DOM 里写入一个可见的错误提示
2. 成功/加载中/失败，三种状态用不同颜色标记
3. 在页面底部加一句提醒，告诉用户要用 HTTP 服务器打开

### 效果？

出问题了用户马上能看到，不会再一脸茫然地盯白屏。

## 第 11 步：国界线精度升级——小国家也能看见

### 原来的问题

原版用的是 110m 精度的世界地图（约 120KB），这是 TopoJSON 提供的最低精度。国界线被大幅简化，弯弯曲曲的边界变成了折线段，小国家（新加坡、卢森堡）直接消失了

### 改进思路

换成 50m 精度（约 450KB），精度提升近 4 倍，文件大小只增加约 300KB——加载时间多 200 毫秒，完全感觉不到

国界线弯曲度提升、海岸线细节丰富（挪威峡湾能看出来了）、小国家可见、边界不再是折线。

## 第 12 步：颜色全面重设计——色盲也能看懂

### 原来的问题

原来的 YlOrRd（黄-橙-红）色板有个致命缺陷：**红色盲（\~1% 男性）看到 M3\~M8 全是一种棕色，完全分不清**；绿色盲（\~6% 男性）在 M2\~M7 之间黄橙红混淆。

### 改进思路

颜色是地震可视化最重要的，我们做了三件事：

1. **换色板**：YlOrRd → Viridis（紫→蓝→绿→黄）。Viridis 是学术界经过大量 CVD（色觉障碍）模拟验证的色板，对所有类型色盲都友好。
2. **加纹理**：光换颜色还不够——万一有人完全看不到颜色呢？我们给每个震级区间画了不同方向的填充线。
3. **给用户选择权**：两个按钮，让你自由切换。"安全色板"模式用 Viridis，"纹理叠加"模式在颜色上面加图案。

同时把所有 UI 上的红色统一换成了色盲安全的暖橙色，文字对比度也提升

### 效果？

- 色盲用户：Viridis 模式下 M0\~M8 全段可辨
- 完全无色觉用户：开纹理叠加，靠线条方向/密度区分震级
- 普通用户：两种模式随意切换，按自己喜好来

## 第 13 步：浅色/暗色双主题

### 原来的问题

一开始用的是深色主题（GitHub Dark 风格），但有人喜欢白天用浅色的界面。而且作为对照原版的设计，浅色更接近 Observable 的默认风格。

### 改进思路

做一个主题切换按钮，默认白色背景，需要的时候一键切到暗色。用 `localStorage` 记住你的选择，下次打开还是你喜欢的主题。

### 效果

打开默认白底（和原版 Observable 的视觉风格接近），点击 ☀️/🌙 按钮 → 秒切暗色主题。刷新页面保持上次选择。
